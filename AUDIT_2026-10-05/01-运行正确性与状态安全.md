## CFI-01 · P1 · 验证未提交配置会迁移真实学习状态

定位：`package/luci-app-cloudflare-ip/root/usr/bin/cf-ip-auto-v2:51–69、653–659，root/usr/libexec/cf-ip/candidate-rill.sh:99–139（后者路径同一 package 前缀）`。

审计证据：已复现：仅调用 cmd_validate_config 校验候选域名，未执行 UCI commit，返回 success=true，但现存 model state 与 qualification 从原路径被移到 quarantine。load_config 无条件调用 context_guard，包含 Rill 关闭的情况；LuCI utils.js 在 safeApply 前调用验证。受影响的是已学习状态和未反馈决策的 lineage，取消保存也不能撤销。见 evidence/cf-repro.log。

### 必须实现

1. 把 load_config 拆成“读取/合并/语义校验配置”与“已提交配置的状态协调”两层。前者不得创建目录、轮换 lineage、写 meta/cadence、迁移文件或拒绝 pending feedback。
2. cmd_validate_config、只读 diagnostics/self-check/status 必须仅使用前者；禁止用环境变量临时绕过再忘记恢复的方式隐藏副作用。
3. 仅在真正执行写操作、已取得阶段 1 的统一锁、重新读取已提交 UCI 后执行 context_guard。guard 的 fingerprint 必须由真实提交配置计算，不能来自浏览器候选 JSON。
4. 初始化无状态的行为也要放进明确的写入口；错误验证不能顺便初始化状态。保留已有指纹、schema、quarantine 与 pending-feedback 兼容规则。
5. 搜索所有 load_config/context_guard 调用，逐个标注只读/写入语义，防止 --validate-config 之外仍发生相同副作用。

### 验收测试

- 构造旧 fingerprint、model、qualification、pending feedback、cadence/meta；记录内容哈希和目录清单。校验不同域名候选后，所有持久文件、lineage、目录清单完全不变。
- 同样测试无 Rill 状态、rill_enabled=0、非法候选、校验后用户取消、连续两次候选校验。
- 提交相同配置后运行：无迁移。提交不同上下文后运行：在锁内迁移一次；重复运行不二次轮换。
- LuCI staged validation 的现有测试必须继续通过，不得用直接保存候选到 UCI 的方式“修复”。

## CFI-02 · P1 · 手动同步及其他写入口缺少统一互斥和失败清理

定位：`root/usr/bin/cf-ip-auto-v2:368–370、610–634、662–684；同目录事务库 transaction.sh 和 run_cleanup/run_v2`。

审计证据：已复现：cmd_sync_explicit 在 txn_prepare 后停止代理失败，直接返回错误，仍保留 PREPARED snapshot 与 CFIP_STOPPED_MODE=passwall，没有 rollback/restore。该入口没有 acquire_lock、EXIT/INT/TERM trap；run_v2 的 context_guard 又发生在拿锁前。OpenClash restore、Rill reset 等写入口也需纳入互斥审查。模拟只注入服务失败，没有实际停止用户服务。

### 必须实现

1. 先列全所有改变代理、UCI、Rill 状态、备份、cron 的 CLI/RPC 入口。统一使用同一个主机写锁；拿锁前只读取安全参数，不做 context_guard 或快照改写。
2. 为 --sync-passwall/--sync-openclash 使用与 run_v2 相同的事务生命周期。准备快照前安装清理处理；服务停止即使部分失败，也要恢复已停服务和原配置。
3. 成功提交才清除回滚义务。任何早返回、超时、INT、TERM 进入同一幂等 cleanup；不能把原始失败码覆盖成回滚成功码。
4. 回滚失败保留可诊断快照并报告 recovery-required，不输出 success=true；重复 cleanup 不得重复破坏已恢复配置。锁只能由拥有者释放。
5. restore-backup/reset/source-refresh 等共享写入必须锁内重新检查前置条件；只读请求不等待长写操作也不能顺带迁移状态。避免嵌套拿锁死锁，明确由入口持锁、底层只执行。
6. 保留单次必要重启和服务原始 active/enabled 状态；不得改成所有服务无条件 restart。

### 验收测试

- stop 第一个代理成功、第二个失败；apply/readback/probe/commit 各边界失败；验证原配置字节、代理状态恢复、返回非零、锁释放。
- 在停止后、写配置后和提交前分别发 INT/TERM，检查子进程树清理和回滚；不能只测试正常退出。
- 两个 sync，以及 run 与 sync/reset/restore 同时启动：第二个明确 busy，任何状态文件不得交错写。
- 在 context_guard 内设置屏障，与并发验证/运行竞争；确认只有持锁写进程迁移。
- 重复执行 cleanup；注入恢复失败，确认保留快照和人工恢复信息。执行 transaction-*、signal-child-tree-rollback、service-state-preservation、sync-single-restart 等既有测试。

## CFI-03 · P2 · 默认复用路径把未知丢包率写成 100% 导致成功 IP 被拒绝

定位：`root/usr/libexec/cf-ip/reuse.sh:74、87–95；observe.sh:165–168`。

审计证据：已复现：复用构造的候选只有 ip/family 等字段，没有 lossRate。post_apply_probe 使用 lossRate // 1，成功 HTTP 探测仍输出 lossRate=1；默认 gate 要求 <=0.25，因而拒绝。日志中 validated=true 与 probes lossRate=[1] 同时存在。

### 必须实现

1. 先写失败回归，保持默认阈值，不通过提高阈值掩盖问题。区分历史测量丢包、当次 HTTP 可用性和未知测量三种信息。
2. 从具备时间/配置上下文匹配的历史样本携带有效 lossRate；没有可信历史值时输出 null/unknown，并明确复用准入政策：需要重测或仅采用已实际测得的 HTTP 指标。未知不能伪造为 0，也不能伪造为 1。
3. probe、reuse gate、状态展示、reward/holdout 消费者使用同一字段语义；jq 的 // 会把 false 当缺失，要逐项检查。
4. 本次健康检查失败继续 fail-closed，历史统计不能覆盖 success=false。过期历史、不同域名/族/配置指纹的样本不得复用。
5. 顺便明确 savedProbes/savedRuntimeSeconds 的计算：验证耗时不是节省耗时，无法建立完整基线时使用 null 或命名准确的 validation 指标，不能宣称未经测量的收益。

### 验收测试

- 默认配置、成功 HTTP、有效低丢包历史应进入复用成功分支；高丢包必须拒绝。
- 缺失丢包、丢包为 0、null、过期样本、指纹变化分别有明确预期，不得默认判为“优质”。
- 同一 IP HTTP 失败/TTFB 超阈值仍拒绝。IPv4/IPv6、多个 IP、部分失败覆盖。
- 状态和 reward 中没有伪造的 100%/0% 丢包；实际发出的验证 probe 数计数正确。

## CFI-06 · P2 · OpenClash TSV 读取折叠空列造成字段错位

定位：`root/usr/libexec/cf-ip/openclash-readback.sh:19、38、60–67`。

审计证据：已复现：合法 vless/ws 模板省略 tls，输出 TSV 的空 tls 列被 IFS=tab read 折叠。实际解析 tls=ws、network=example.com、Host 为空，协议筛选返回 1。既有 tls:false fixture 未覆盖空列。

### 必须实现

1. 取消用 shell 空白 IFS 解码含可空列的 TSV。选用明确可保留空值的结构化 JSON 记录，或非空白分隔并严格转义；不使用 eval。
2. actual_mapping 和 intended_from_templates 必须共用同一字段解码，不只修一侧。将空 tls、network、servername、Host 保持在各自字段。
3. 明确支持的 YAML 形态和模板边界；无依赖增加时采用保守 parser，遇到不支持的结构给明确错误，不能跨 proxy block 拼字段或安静丢掉所有节点。
4. 保持 complete-record readback：server、SNI、Host、network、名称和数量都匹配，不能退化成只检查 IP 存在。
5. 不引入把代理 credentials 写入诊断日志的行为。

### 验收测试

- tls 缺失与 false/true，各自组合 ws/xhttp/grpc/TLS；Host/SNI 为空、首中尾连续空字段，解析准确。
- 每个 proxy 的值与下一 block 独立；同 IP 不同 Host/SNI 必须判失败。
- 候选名称含空格和允许字符；不支持 YAML inline/anchor 等给可理解错误。运行 openclash-* 和 intended-mapping-negative 测试。

## CFI-07 · P2 · CFST 下载回退把旧缓存标记为新版本

定位：`root/usr/bin/cf-ip-auto-legacy:521–533、580–585、599–603、620–621`。

审计证据：静态确认：元数据宣布新 version，下载失败或新归档非法时，将旧 archive 与“新 version”传给 install_speedtest_archive，该函数写新 version.txt。下一次检测 version==old_version 且 binary 存在，跳过新版本下载。

### 必须实现

1. 缓存归档保存自身版本、来源、hash 元数据，回退仅使用该归档的真实已验证版本。不能使用当次远端 latest tag 给旧文件贴标签。
2. 对已有缓存无可靠版本的情况，保留 unknown/旧 binary 已知版本，明确标记 fallback，不声称升级成功；下次有网时仍尝试最新下载。
3. 新归档先校验 hash、限制解包路径并在临时目录核验目标可执行文件；binary、archive 元数据和 version.txt 在成功后协调提交，失败保持旧可用组件。
4. 覆盖 metadata 不可用、curl 失败、HTML、tar 非法、digest 不匹配、落盘失败等分支，错误代码和回退可用性分别表达。
5. 兼容已有 version.txt，没有必要删除用户有效的旧缓存。

### 验收测试

- 缓存 v1、远端 v2：下载失败后仍显示 v1/fallback，随后网络恢复确实再次下载 v2。
- 非法新 tar、HTML、元数据失败同样不误标 v2；缓存无版本不凭空生成 v2。
- 新 v2 真实安装完成才更新版本；提取/权限/原子替换失败维持旧 binary/metadata。
- cfst-version-contract 继续通过，并新增专门的回退版本契约测试。

## CFI-08 · P2 · 停止服务没有正确更新带空格的 JSON 状态

定位：`root/etc/init.d/cf_ip:113–117；root/usr/bin/cf-ip-auto-v2 的 write_status/cmd_status`。

审计证据：静态确认：stop_service 只替换字面 "running":true，但 jq -n 生成 "running": true 的格式；正常状态不会被改成 false。只移除 cron 也不代表已有后台运行已经停止，running 字段必须定义准确语义。

### 必须实现

1. 用结构化 JSON 写入停止状态：在同目录创建临时文件，jq 校验，原子替换，保留其它字段；不得用依赖 JSON 空白的 sed。
2. 明确 status 中 enabled/scheduled/jobRunning 的关系，停止计划后更新正确字段，UI/RPC/CLI 同义。已有 running 若表示服务启用，停止必须 false；若表示作业活跃，应保留活跃真实状态而另报 disabled。
3. 审查后台 run 与 stop 的竞争，持锁协调状态发布。若产品定义 stop 要取消作业，采用验证过的进程身份与信号让事务 cleanup 恢复代理；不得只按残留 PID kill 任意进程。
4. 不把 corrupt status 修成看似健康；没有状态文件时有可解释的默认输出。

### 验收测试

- compact、jq pretty、不同 key 顺序 JSON 停止后语义一致，保留其它信息。
- 无文件、空文件、非法 JSON、写入/rename 失败不输出虚假成功。
- 停止与正在执行的 run 并发，状态不被旧配置覆盖成“已启用”；服务/作业语义有测试和文档。
- cron-contract、disabled-cron-contract、status/RPC 状态测试通过。
