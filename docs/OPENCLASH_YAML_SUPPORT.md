# OpenClash YAML transformation boundary

Intended mappings distinguish an ordinary template from an existing numbered CF variant. Each existing variant contributes its own selected-IP slot once; missing slots are derived from the first matching base-name/domain template. Existing slots retain their own transport and authentication profile. Ordinary templates still expand fully. Neither actual nodes nor conflicting definitions are silently deduplicated: expected and observed generated names must be unique, with exact IP/SNI/network/Host matching before publication. The real-renderer transaction regression covers repeated updates, unchanged selections, growth, a missing first slot and duplicate-node refusal using a jq fixture without regex support.

Proxy sequence entries must be indented under `proxies`. Unindented YAML sequences are refused explicitly because the line mapper does not handle them; they must not produce an empty successful mapping.

Endpoint transformation and readback support a conservative block-form `proxies` sequence. Each proxy starts with `- name:`. Node identity fields (`type`, `server`, `tls`, `network`, `servername`) use scalar values directly inside that node; the supported transport header uses `Host`. Mapping is scoped to the top-level `proxies` section. Generated variants are written before leaving that section; the tested group/rule tail is retained on repeated transformations.

The entry check rejects inline root/entry maps, alias/merge/anchor/tag or block-scalar forms in the proxy area, duplicate mapped fields, nested node identity fields, duplicate `proxies` sections and tabs. It reports the offending line and reason. Unsupported input is rejected before config temporary files/backups/publication in Legacy and standalone engines, and before actual/intended mapping output in v2. The self-contained engines embed the same check; a conformance test compares their function definitions.

The writer and readback now also require Ruby/Psych, normally provided by OpenClash, to parse exactly one complete YAML document before mutation. The AST is inspected without instantiating tagged objects. Malformed tails, duplicate mapping keys anywhere, complex/implicitly typed keys and ambiguous mapped scalars reject. Quoted literal `#` is preserved; mapped inline comments, interpreted escape sequences and quoted mapped keys are refused when the line reader cannot represent their parsed meaning exactly. This is an explicit supported-input boundary, not support for arbitrary YAML or every Clash option. A missing parser fails before mutation; PassWall does not require Ruby.

Both self-contained renderers validate their generated candidate before creating a backup or publishing it. Generated names requiring YAML quoting are serialized safely; an existing Host is updated rather than supplemented by a second mapped Host. Backup restoration validates the private restore candidate too. Whole-document syntax acceptance does not prove proxy semantics, controller health or deployment success; the independent transaction/readback/service gates still apply. Existing user files are never rewritten merely to enter the supported subset.

Current regression scripts: `tests/openclash-document-boundary.sh` (all three engines, malformed documents, duplicate keys, scalar representation, missing parser, literal comment character and invalid generated output), `tests/openclash-yaml-boundary.sh`, `tests/openclash-transform-unsupported.sh`, `tests/openclash-transform-section.sh`, the two-engine fifteen-protocol matrix, positive/negative readback and actual renderer isolation. Software fixtures do not replace the separate real-device gate. Y01's partial-document acceptance is repaired in source; the final changed SHA still needs full qualification and separate deployment coverage.
