### 为什么 tag 目标不是 `90dfc13`

`release.yml` 与发布策略要求正式包只从 **`main` 的成功 exact-SHA CI** 运行发布。`90dfc13` 是 PR 分支头，不是 `main` 提交。推荐流程：

1. 用户授权后用 **Create a merge commit** 合并 PR #25（`main` 当前是 PR 头的祖先，merge 不产生冲突，`tree(M) = tree(P)`）。
2. 等 `main` 上 `M` 的 CI 全绿，下载 `M` 的 qualification 与两个公开包。
3. 以 `M` 为 `--target` 创建 `v2.6.0-8` tag/Release。

如果用户明确接受“直接在 PR 头打 tag”的一次性例外，则 tag 目标为阶段 G 提交 `P`，使用 `P` 的 exact-SHA run；本文件与报告会标注该例外。

### 授权后命令（草稿，未执行）

```sh
# 1) 合并（用户授权后）
gh pr merge 25 --merge --delete-branch=false

# 2) 取 main 上 merge commit 与 CI run
M_SHA=$(gh api repos/hello-yunshu/luci-app-cloudflare-ip/commits/main --jq .sha)
gh run list --branch main --commit "$M_SHA" --limit 3

# 3) 下载同 run/attempt 的资产（RUN_ID 以第 2 步为准）
RUN_ID=<main CI run id>
gh run download "$RUN_ID" -n qualification-evidence-run-"$RUN_ID"-attempt-1 -D /tmp/r8/qual
gh run download "$RUN_ID" -n luci-app-cloudflare-ip-ipk-v24.10.5-run-"$RUN_ID"-attempt-1 -D /tmp/r8/ipk
gh run download "$RUN_ID" -n luci-app-cloudflare-ip-apk-v25.12.0-run-"$RUN_ID"-attempt-1 -D /tmp/r8/apk
(cd /tmp/r8 && sha256sum ipk/*.ipk apk/*.apk)

# 4) 创建 tag + Release（用户单独授权）
gh release create v2.6.0-8 --target "$M_SHA" --title v2.6.0-8 \
  --prerelease --notes-file docs/audits/next-release-release-notes-v2.6.0-8.md \
  /tmp/r8/ipk/luci-app-cloudflare-ip_2.6.0-r8_all.ipk \
  /tmp/r8/apk/luci-app-cloudflare-ip-2.6.0-r8.apk \
  /tmp/r8/qual/SHA256SUMS /tmp/r8/qual/qualification.json
```

`release.yml` 的自动路径只接受 `main` + `channel=prerelease`；当前 channel 为 `stable`，自动发布会被 guard 拒绝，因此本版本必须使用上面的受控人工 Release 步骤。
