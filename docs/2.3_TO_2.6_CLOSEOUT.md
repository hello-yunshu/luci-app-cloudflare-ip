# 2.3–2.6 implementation closeout

This closeout records what is implemented in the current source tree and keeps
replay, package, device, and soak evidence separate.

## 2.3 bounded evidence harness

`docker/2.3/` reuses the production Adaptive scheduler and audit builder. Its
fixtures cover pool sizes 8, 16, 32, 64, 128, 256, and 512; IPv4, IPv6, and
both; IP counts 1, 4, and 6; cold, stable, mixed, stale, and degraded history;
Shadow and Guarded; expansion and fallback. The output includes `plannedK`, unique probes,
timing fields, recall, insufficiency, fallback, and expansion measures.

The output is explicitly `environment=macbook-docker-replay` and
`timingMode=replayed`. It is evidence for repeatability and schema coverage,
not real network latency, wall-clock savings, or a production Go decision. The
harness never tunes
configuration, writes UCI, uploads network data, or trains a policy.

## 2.4–2.5 conservative operating framework

The context policy is deterministic and currently reports
`conservative-default` with `supported=false` because the replay evidence does
not justify context-specific parameter changes. Operational Health persists
`healthy`, `warning`, or `degraded` with bounded reason codes and a 100-record
atomic history store. Its rolling window is the last 20 completed runs with a
minimum of 5 meaningful samples, and applies only
conservative guardrails: shorter audits, shorter reuse horizons, Shadow mode,
or reuse disablement. It cannot promote Adaptive or Candidate authority.

## 2.6 intelligence surface

The existing Intelligence page now exposes Current Endpoint, System Health,
Adaptive state, Candidate state, next audit/optimize, current context policy,
why the run happened, reason codes, and bounded recent history. No second
learner, percentage-based AI claim, or large dashboard was added.

## Verification boundary

Host syntax, ShellCheck, JSON/JavaScript checks, the existing host contract
matrix, new `run_v2` lifecycle/health/history tests, and host replay passed.
Docker replay is defined and CI-gated but is not executable in the current
environment because the local Docker daemon is unavailable; no real-network
evidence is fabricated. Physical OpenWrt coverage and soak are
`SKIPPED (user-approved)`; replay and package checks do not upgrade those
states. The release workflow treats docs/plans-only commits as a clean no-op
and still requires qualification for code, package, workflow, or release
contract changes.
